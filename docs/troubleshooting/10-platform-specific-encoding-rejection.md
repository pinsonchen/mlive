# 场景 10：平台编码格式不兼容

## 现象描述

推流连接成功，但平台随即自动断开，或直播间显示"格式不支持"、"编码错误"，部分平台给出错误代码（如抖音的 `4101`、YouTube 的 `Generic stream ingestion failed`）。

## 判定步骤

```
推流后平台提示"格式不支持"或自动断流
│
├─ 步骤 1：检查视频编码格式
│   OBS → 设置 → 输出 → 编码器
│   └─ 使用 H.265/HEVC 或 AV1（平台不支持）→ 修复动作 A（改为 H.264）
│
├─ 步骤 2：检查音频编码格式
│   设置 → 输出 → 音频编码器
│   └─ 使用 Opus/MP3（平台要求 AAC）→ 修复动作 B（改为 AAC）
│
└─ 步骤 3：检查分辨率/帧率是否超出平台限制
    设置 → 视频 → 查看输出分辨率和帧率
    └─ 超出平台上限 → 修复动作 C（调整至平台允许范围）
```

## 修复动作

### 动作 A：切换到 H.264 编码

大多数平台**仅支持 H.264**（AVC），不接受 H.265/HEVC 或 AV1：

```
OBS → 设置 → 输出 → 输出模式：高级
  视频编码器：
    × H.265 (NVENC) / HEVC / AV1   ← 不兼容
    ✓ H.264 (NVENC) / x264 / QSV H.264  ← 使用这些
```

### 动作 B：音频编码改为 AAC

```
OBS → 设置 → 输出 → 音频编码器：AAC
  码率：128 kbps（推荐）或 160 kbps
  采样率：44100 Hz 或 48000 Hz
```

各平台音频要求：

| 平台 | 编码 | 推荐码率 | 采样率 |
|------|------|---------|--------|
| Bilibili | AAC | 128 kbps | 44100 Hz |
| 抖音 | AAC | 128 kbps | 44100 Hz |
| YouTube | AAC | 128-384 kbps | 44100/48000 Hz |
| Twitch | AAC | 160 kbps | 44100 Hz |

### 动作 C：调整至平台允许的分辨率/帧率

各平台推流参数上限：

| 平台 | 最大分辨率 | 最大帧率 | 最大视频码率 |
|------|----------|---------|------------|
| Bilibili | 1920×1080 | 60 fps | 10 Mbps |
| 抖音 | 1920×1080 | 30 fps | 8 Mbps |
| YouTube | 3840×2160 | 60 fps | 51 Mbps |
| Twitch | 1920×1080 | 60 fps | 6 Mbps |

```
OBS → 设置 → 视频
  输出（缩放）分辨率：根据目标平台选择（如 1280×720 或 1920×1080）
  帧率：30（通用）或 60（仅支持 60fps 的平台）

OBS → 设置 → 输出 → 视频码率：
  抖音推荐 ≤ 6000 kbps
  Twitch 推荐 ≤ 6000 kbps
  Bilibili 推荐 ≤ 8000 kbps
```

### 额外：关键帧间隔设置

大多数平台要求关键帧间隔为 **2 秒**：

```
OBS → 设置 → 输出 → 关键帧间隔（秒）：2
（设为 0 表示自动，部分平台不接受，建议显式填写 2）
```

## 验证方法

1. 修改参数后重新推流，等待 30 秒确认连接稳定。
2. 检查平台直播后台"流信息"或"监控"面板，确认显示正确的编码信息（H.264、AAC）。
3. 在 OBS 日志（`帮助 → 日志文件 → 当前日志`）中搜索 `error` 关键词，确认无编码相关报错。

```bash
# 在终端快速搜索日志中的错误（macOS）
grep -i "error\|reject\|disconnect" ~/Library/Application\ Support/obs-studio/logs/$(ls -t ~/Library/Application\ Support/obs-studio/logs/ | head -1)
```
