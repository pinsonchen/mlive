# 场景 14：音频设备冲突

## 快速解决（≤3 步）

> 1. **指定具体设备**：OBS → 设置 → 音频，将麦克风/桌面音频改为具体设备名（非"默认"），断开重连。
> 2. **检查轨道映射**：确认推流音频轨道包含麦克风+桌面音频，且未被静音。
> 3. **消除冲突源**：关闭其他占用音频设备的程序，启用"噪声抑制"和"噪声门"滤镜。

若以上 3 步未解决，再阅读下方完整判定流程。

## 现象描述

推流画面正常但观众听不到声音，或出现电流声、重复回声、杂音等音频异常。

## 判定步骤

```
推流画面正常但音频异常
│
├─ 步骤 1：OBS 混音器中麦克风是否有绿色电平跳动？
│   查看 OBS 主界面底部混音器
│   └─ 无信号 → 修复动作 A（重新选择音频设备）
│
├─ 步骤 2：混音器有信号但观众听不到
│   检查音频轨道映射与静音状态
│   └─ 轨道映射错误 → 修复动作 B
│
└─ 步骤 3：观众能听到但有杂音/回声
    检查是否有其他程序占用音频设备
    └─ 有冲突 → 修复动作 C
```

## 修复动作

### 动作 A：重新选择音频设备

OBS → 设置 → 音频：

1. 麦克风/辅助音频：选择具体设备名（如"Blue Yeti"），不要选"默认"。
2. 桌面音频：选择具体输出设备。
3. 物理断开音频设备再重新连接。

```
设置 → 音频
  麦克风/辅助音频设备：Blue Yeti (USB Audio)  ← 不要选"默认"
  桌面音频：MacBook Pro 扬声器
```

### 动作 B：修复音频轨道映射

1. OBS → 编辑 → 高级音频设置。
2. 确认麦克风和桌面音频的"轨道"列中 Track 1 已勾选（Track 1 通常是推流轨道）。
3. 确认对应来源未被静音（混音器中扬声器图标未关闭）。

### 动作 C：消除音频冲突

1. 关闭其他占用音频设备的程序：
   - 语音通话（微信、钉钉、Zoom）
   - 音乐播放器
   - 其他录屏软件
2. 在 OBS 中为麦克风添加滤镜：
   - 噪声抑制（RNNoise）
   - 噪声门（关闭阈值 -32dB，开启阈值 -26dB）

```bash
# macOS 检查音频设备占用
lsof | grep -i "coreaudio"
```

## 验证方法

1. OBS 混音器中麦克风出现绿色电平跳动。
2. 推流后用另一台设备观看直播，确认声音清晰、无杂音。
3. 同时说话和播放桌面音频，确认两路均正常输出。
