# 场景 07：CPU 编码占用过高

## 现象描述

直播过程中出现画面卡顿、掉帧严重，任务管理器显示 CPU 使用率持续 90%+，OBS 状态栏"编码超载"警告。

## 判定步骤

```
CPU 占用高，直播卡顿/掉帧
│
├─ 步骤 1：确认当前编码器类型
│   OBS → 设置 → 输出 → 编码器
│   └─ 使用 x264（软件编码）且 CPU 高 → 修复动作 A（切换硬件编码）
│
├─ 步骤 2：检查编码预设
│   设置 → 输出 → CPU 使用预设
│   └─ 预设为 medium/slow/slower → 修复动作 B（改为 veryfast）
│
└─ 步骤 3：检查场景复杂度
    来源列表中是否有大量浏览器来源、高分辨率视频叠加
    └─ 来源过多/分辨率过高 → 修复动作 C（精简场景或降低分辨率）
```

## 修复动作

### 动作 A：切换到硬件编码器

```
OBS → 设置 → 输出 → 输出模式：高级
  视频编码器：
    NVIDIA GPU → NVENC H.264（推荐）
    AMD GPU   → AMD HW H.264（AMF）
    Apple M 芯片 → Apple VT H264 Hardware Encoder
    Intel 核显  → QSV H.264
```

硬件编码可将 CPU 占用从 80%+ 降至 5-15%，画质损失极小。

### 动作 B：调整 x264 编码预设（保留软件编码时）

```
设置 → 输出 → CPU 使用预设：veryfast 或 superfast

预设速度对比（从快到慢，CPU 占用递增）：
  ultrafast → superfast → veryfast → faster → fast → medium → slow
                ↑ 推荐直播使用范围 ↑
```

### 动作 C：精简场景与降低分辨率

```
OBS → 设置 → 视频
  基础（画布）分辨率：1920×1080 → 1280×720
  输出（缩放）分辨率：1280×720
  帧率：60 FPS → 30 FPS（CPU 占用减少约 40%）
```

清理不必要的来源：

```
来源列表 → 删除或隐藏未使用的：
  - 浏览器来源（每个浏览器来源约占 3-8% CPU）
  - 高分辨率图片/视频背景
  - 未使用的场景
```

## 验证方法

1. 推流期间打开任务管理器（Windows）或活动监视器（macOS），CPU 使用率应 < 60%。
2. OBS 状态栏"编码超载"警告消失，掉帧计数为 0。
3. 查看 `OBS → 查看 → 统计`，"丢弃帧（编码）"为 0%。
