# 场景 06：多平台部分推流失败

## 快速解决（≤3 步）

> 1. **单独测试失败平台**：在 obs-multi-rtmp 中只启用失败那路，确认其推流地址、密钥、编码格式合法。
> 2. **降低单路码率**：总推流码率 ≤ 上行带宽 × 0.6，否则减少同推平台数。
> 3. **绕过中间转发**：若使用 restream.io 等转发服务失败，改为 OBS 直推该平台。

若以上 3 步未解决，再阅读下方完整判定流程。

## 现象描述

使用多路推流工具（OBS 多输出插件、restream.io、nginx-rtmp 等）同时向多个平台推流时，部分平台收到信号，另一些平台显示无信号或断连。

## 判定步骤

```
多平台推流，部分失败
│
├─ 步骤 1：确认失败的是哪个输出
│   检查每个推流输出的状态（插件日志或转发服务状态页）
│   └─ 特定平台持续失败 → 修复动作 A（排查该平台配置）
│
├─ 步骤 2：检查总带宽是否足够
│   总推流码率 = 各路码率之和
│   执行：speedtest-cli --upload
│   └─ 上行带宽不足 → 修复动作 B（降低各路码率或减少路数）
│
└─ 步骤 3：检查中间转发节点（如使用 restream.io）
    登录转发服务控制台，查看该平台连接状态
    └─ 转发服务到该平台失败 → 修复动作 C（绕过转发，直推）
```

## 修复动作

### 动作 A：排查特定平台配置

使用 OBS 多输出插件（obs-multi-rtmp）时，检查失败平台的推流配置：

```
OBS → 工具 → 多路推流 → 选择失败的输出 → 检查：
  ✓ 推流地址格式正确（rtmp:// 开头）
  ✓ 推流码未过期
  ✓ 编码参数在平台允许范围内（如抖音要求 H.264，不支持 H.265）
```

各平台编码限制参考：

| 平台 | 编码 | 最大码率 | 最大分辨率 |
|------|------|---------|-----------|
| Bilibili | H.264 | 10 Mbps | 1080p60 |
| 抖音 | H.264 | 8 Mbps | 1080p30 |
| YouTube | H.264/H.265 | 51 Mbps | 4K60 |
| Twitch | H.264 | 6 Mbps | 1080p60 |

### 动作 B：调整多路码率

```
总上行带宽利用率建议 ≤ 70%

示例（上行 20 Mbps）：
  B站：4000 kbps
  抖音：3000 kbps
  YouTube：4000 kbps
  合计：11000 kbps ≈ 55%（安全范围内）
```

在 obs-multi-rtmp 中为每个输出单独设置码率：`输出设置 → 视频码率`。

### 动作 C：直推替代转发

如果 restream.io 等中间服务到某平台不稳定，改用 nginx-rtmp 本地分发：

```nginx
# nginx.conf 片段
rtmp {
    server {
        listen 1935;
        application live {
            live on;
            push rtmp://live-push.bilivideo.com/live-bvc/?streamname=xxx;
            push rtmp://vs-push.douyucdn.cn/live/yyy;
        }
    }
}
```

```bash
# 启动 nginx-rtmp
nginx -c /path/to/nginx.conf

# OBS 推流到本地 nginx
# 服务器：rtmp://127.0.0.1/live  推流码：stream
```

## 验证方法

1. 在每个平台直播后台确认"直播状态"均显示"直播中"。
2. 用不同设备分别打开各平台直播间，确认画面正常。
3. 保持 5 分钟，确认所有平台无断流。
