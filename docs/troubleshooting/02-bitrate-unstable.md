# 场景 02：码率不稳定

## 现象描述

OBS 底部状态栏码率数值剧烈波动（如 4000 kbps → 800 kbps → 3500 kbps），观众反馈画质忽好忽坏、频繁缓冲。

## 判定步骤

```
码率持续波动 / 观众卡顿
│
├─ 步骤 1：检查本机上行带宽
│   执行：speedtest-cli --upload
│   或访问 fast.com 测速
│   └─ 上行 < 设定码率的 1.5 倍 → 修复动作 A（降低目标码率）
│
├─ 步骤 2：检查 OBS 丢包率
│   OBS 状态栏右侧查看"丢弃帧"百分比
│   └─ 丢帧 > 5% → 修复动作 B（启用动态码率或换节点）
│
└─ 步骤 3：排查本地网络干扰
    运行期间关闭其他下载/视频会议
    └─ 关闭后稳定 → 修复动作 C（QoS/带宽预留）
```

## 修复动作

### 动作 A：调整目标码率

经验公式：目标码率 ≤ 上行带宽 × 0.6（预留余量）。

```
上行 10 Mbps → 最大推流码率建议 ≤ 6000 kbps
上行 4 Mbps  → 最大推流码率建议 ≤ 2400 kbps
```

在 OBS 中调整：`设置 → 输出 → 视频码率`，将"码率控制"改为 **CBR**，填入合理值。

### 动作 B：启用动态码率（自适应）

`设置 → 高级 → 网络`，勾选 **"在拥塞时动态调整比特率（测试版）"**。

若丢帧持续，更换更近的推流节点（参考场景 01 动作 C）。

### 动作 C：网络 QoS 配置

```bash
# macOS：使用流量控制工具检查其他进程占用
nettop -P -n -d

# 终止占用上行带宽的后台进程（示例：关闭 iCloud 同步）
# 系统设置 → Apple ID → iCloud → 暂停同步
```

路由器侧：为 OBS 所在机器开启 QoS 优先级，或为端口 1935/443 设置最高优先级。

## 验证方法

1. 调整后在 OBS 状态栏观察 30 秒，码率波动幅度应 < ±15%。
2. 打开 `查看 → 统计`，确认"丢弃帧"为 0 或极低（< 0.5%）。
3. 用另一台设备观看直播，确认画面流畅无卡顿。
