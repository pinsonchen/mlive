# 网络相关常见问题

## FAQ-005: 推流频繁断开重连

**问题**：直播过程中推流连接频繁断开并自动重连，导致观众端画面中断。

**症状**：
- OBS状态栏反复显示"重连中"
- 观众反馈直播间画面黑屏后恢复
- 丢帧率持续上升

**原因**：
- 网络上行带宽不足或不稳定
- 使用WiFi连接且信号不佳
- 路由器性能不足或过热
- ISP（运营商）对RTMP流量限速

**解决步骤**：
1. 优先使用有线网络（网线直连路由器）
2. 使用 speedtest.net 测试上行带宽，确保 ≥ 推流码率 × 平台数 × 1.5
3. 重启路由器，清除缓存
4. 降低推流码率（如从3000kbps降到2000kbps）
5. 如果使用WiFi，靠近路由器或使用5GHz频段
6. 联系ISP确认是否有上行限速

## FAQ-006: 多平台同步推流时部分平台断流

**问题**：同时推流多个平台时，某些平台正常但其他平台断流。

**症状**：
- 主推流正常，部分Multi RTMP目标断开
- 某个平台频繁断流而其他平台稳定
- 断流平台每隔几分钟自动重连

**原因**：
- 总上行带宽不足以支撑所有平台
- 某平台服务器响应慢导致缓冲区溢出
- 各平台对码率上限要求不同

**解决步骤**：
1. 计算总带宽需求：码率 × 平台数（如2500kbps × 3 = 7.5Mbps上行）
2. 确保实际上行带宽为总需求的1.5倍以上
3. 针对断流平台单独降低码率
4. 检查Multi RTMP插件中各目标的"重连间隔"设置
5. 考虑错开各平台开播时间（先稳定一个再开下一个）

**相关链接**：[推流配置](streaming-config.md)

## FAQ-007: 如何测试上行带宽是否满足推流需求

**问题**：不确定当前网络是否能支撑多平台同步直播。

**症状**：
- 不清楚自己的上行带宽
- 不知道推流需要多少带宽
- 直播时断断续续但不确定是否是网络问题

**原因**：
用户通常只关注下载速度（下行带宽），忽略了直播最关键的上行带宽。

**解决步骤**：
1. 访问 speedtest.net，点击"开始"测速
2. 重点关注"上传"速度（Upload）
3. 计算所需带宽：
   - 单平台：码率 × 1.5（如2500kbps需要约4Mbps上行）
   - 双平台：码率 × 2 × 1.5（需要约8Mbps上行）
   - 三平台：码率 × 3 × 1.5（需要约12Mbps上行）
4. 如果带宽不足：
   - 降低码率（牺牲画质）
   - 减少同步平台数量
   - 升级宽带套餐（重点升级上行）
   - 考虑使用4G/5G热点作为备用

**相关链接**：[码率设置指南](bitrate.md)

## FAQ-008: 直播延迟过高（观众反馈画面滞后）

**问题**：观众反馈直播画面延迟很大，互动不流畅。

**症状**：
- 观众看到的画面比实际慢10秒以上
- 弹幕互动有明显时差
- 不同平台延迟不一致

**原因**：
- 各平台CDN转码和分发有固有延迟（通常3-10秒）
- 码率过高导致编码和传输延迟增加
- OBS关键帧间隔设置过大
- 网络拥塞增加了传输时间

**解决步骤**：
1. 了解各平台的固有延迟（正常范围3-10秒，无法完全消除）
2. 在OBS设置中将关键帧间隔设为2秒
3. 使用"低延迟"或"超低延迟"编码预设（如果平台支持）
4. 适当降低码率以减少传输延迟
5. 选择距离最近的推流服务器节点
6. 避免在网络高峰时段直播

**相关链接**：[推流配置](streaming-config.md)
